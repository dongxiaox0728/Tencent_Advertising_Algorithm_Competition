# Long-tail Distribution / Class Imbalance

**不处理的话会有哪些问题？**

## **1. 模型退化成"永远预测多数类"**

这是最常见的问题。假设 95% 负样本、5% 正样本，模型发现只要无脑输出"负"，准确率就有 95%，loss 也很低。梯度更新的信号几乎全来自负样本，模型完全没有动力学习正样本的特征。

## **2. 评估指标失真**

Accuracy 会虚高，掩盖真实问题。这时候应该看：

- **Precision / Recall / F1**：关注少数类的识别能力
- **AUC-ROC**：衡量模型区分正负的整体能力
- **PR曲线**：在极度不平衡时比 ROC 更有信息量

实际工程里，一个 Accuracy 98% 的模型，查一下 Recall 发现是 0，这种情况很常见。

## **3. 梯度被多数类"淹没"**

每个 mini-batch 里正样本可能只有 1-2 个，负样本有几十个。参数更新的方向几乎由负样本决定，正样本的梯度信号太微弱，完全学不进去。

## **4. 决策边界偏移**

模型学到的决策边界会朝少数类一侧压缩，即使少数类样本离边界很近，模型也倾向于把它归入多数类。


## 解决方法


分三大类来讲，从数据层、算法层、训练策略层分别入手：

---

**一、数据层（治本）**

**过采样（Oversampling）**：把少数类样本复制或合成更多。

- 最简单的是直接重复少数类样本，但容易过拟合
- **SMOTE**（Synthetic Minority Oversampling Technique）：在少数类样本之间插值，生成新的合成样本，比直接复制好很多

**欠采样（Undersampling）**：减少多数类样本。

- 随机丢弃多数类样本，简单但会损失信息
- **Tomek Links**：删掉多数类里靠近决策边界的样本，清理边界

**两者结合**：先欠采样压缩多数类，再过采样扩充少数类，一起用效果往往更好。

**数据增强**：对少数类做变换（旋转、裁剪、噪声等），人工扩充。在图像任务里非常常用。

---

**二、算法层（改 loss / 模型）**

这就是上面聊过的那些：

- **类别加权 loss**：给少数类更高的 loss 权重
- **Focal Loss**：自动压低易分样本的权重
- **样本加权**：按样本重要性分配权重

除此之外还有：

**Threshold 调整**：模型训练完之后，默认用 0.5 作为分类阈值，但不平衡场景下可以把阈值调低（比如 0.2），让模型更容易预测为正类。这个方法不改训练过程，只改推理阶段，成本最低。

**代价敏感学习（Cost-sensitive Learning）**：显式地定义误分类的代价矩阵，比如"把癌症漏诊"的代价远大于"把健康误诊为癌症"，直接把业务代价嵌入训练目标。

---

**三、训练策略层**

**重采样（Re-sampling）mini-batch**：不改整体数据集，只在每个 mini-batch 里强制保证正负比例，比如每个 batch 里正负各 50%。实现简单，效果稳定。

**两阶段训练**：

1. 第一阶段：用全量数据正常训练，让模型先学会基本特征
2. 第二阶段：只用平衡后的数据 fine-tune 最后的分类层

在大模型和视觉模型里很常见，特征提取部分不受不平衡影响，只需要修正分类头。

**集成方法（Ensemble）**：

- **EasyEnsemble**：从多数类里随机采多个子集，每个子集和少数类组合训练一个模型，最后投票
- **BalancedBagging**：类似 Bagging，但每个基分类器用平衡后的数据训练

---

**方法选型的粗略指导**

|不平衡程度|推荐方向|
|---|---|
|轻度（1:5 以内）|类别加权 loss 就够了|
|中度（1:10 ~ 1:50）|SMOTE + 类别加权，或 Focal Loss|
|重度（1:100 以上）|两阶段训练 + Focal Loss + batch 重采样|
|极度（1:1000+）|考虑换任务形式（如异常检测），或集成方法|

实际项目里一般不会只用一种，**数据层 + 算法层组合**是最常见的做法。先做 SMOTE 或 batch 重采样，再加上 Focal Loss 或类别加权，两个层面同时发力。

# logit 是模型输出的原始分数，经过 sigmoid 变成概率

模型 forward(inputs) 返回一个张量：

logits = model(inputs)   # shape = (256, 1), 其中256是 batch size

所以你的问题答案是：模型输出的是 logit（一个实数），过 sigmoid 后是 0~1 的概率。本质上是一个"软"二分类输出，可以直接用作排序得分，也可以加阈值做硬判断。

logit: 模型输出的原始分数，范围是 (-∞, +∞)，没有经过任何变换。
probability: 经过 sigmoid 变换后的值，范围是 (0, 1)，表示预测为正类的概率。

# 损失函数：怎么衡量"预测得好不好"？

baseline 提供了两种可选，由 --loss_type {bce, focal} 切换。默认是 BCE。

## 方案 1（默认）：Binary Cross Entropy with Logits（BCE）
数学公式：
$$\mathcal{L}{\text{BCE}} = -\frac{1}{N} \sum{i=1}^{N} \Big[ y_i \log(p_i) + (1 - y_i) \log(1 - p_i) \Big]$$

其中 $p_i = \sigma(\text{logit}_i)$。

直觉解读：

如果真实 $y=1$，那么 loss = $-\log(p)$。$p$ 越接近 1，loss 越小；$p$ 接近 0 时 loss 趋于 $+\infty$（"明明是正样本你却预测成负"会受到严厉惩罚）。
如果真实 $y=0$，那么 loss = $-\log(1-p)$。同理对称。
代码（trainer.py:418）：


loss = F.binary_cross_entropy_with_logits(logits, label)

## 方案 2（可选）：Focal Loss
PCVR 的本质难题：正样本极少。比如 1000 个点击里只有 5 个真转化，其余 995 个都是负样本。

普通 BCE 在这种情况下有两个问题：

正负不平衡：模型可以靠"无脑预测全 0" 拿到 99.5% 的"准确率"，但毫无用处。
简单样本主导梯度：那 995 个负样本里大部分模型已经"轻松分对"了（比如 p=0.01），但因为基数太大，它们仍然贡献了梯度的大部分。模型把精力浪费在了已经会的题上。
Focal Loss（论文 1708.02002 何恺明 2017）的解决方案是在 BCE 上加两个修正系数：

$$\mathcal{L}_{\text{Focal}} = -\alpha_t \cdot (1 - p_t)^\gamma \cdot \log(p_t)$$

其中：

$p_t = p$ 当 $y=1$，$p_t = 1-p$ 当 $y=0$（真类的预测概率）
$\alpha_t = \alpha$ 当 $y=1$，$\alpha_t = 1-\alpha$ 当 $y=0$（类别平衡因子）
$(1 - p_t)^\gamma$（难样本聚焦因子）
两个修正各做什么：

(1) $\alpha_t$ 处理类别不平衡：
默认 α=0.1 ⇒ 正样本权重 0.1，负样本权重 0.9。等等？正样本本来就少，为啥还把它的权重压低？
答：因为 PCVR 里负样本太多了，整体梯度被负样本压制；α 是用来反过来"压一下负样本贡献"——这里 baseline 选 0.1 实际上是经验调出来的，对应"重视负样本中的难样本"。具体值要根据你的数据正负比调。

(2) $(1-p_t)^\gamma$ 处理难易样本：

对于一个已经分对的样本（比如 $p_t = 0.95$），$(1-0.95)^2 = 0.0025$，loss 几乎被压到 0 → "你已经会了，下次别再算了"。
对于一个分错的难样本（比如 $p_t = 0.1$），$(1-0.1)^2 = 0.81$，几乎不衰减 → "重点关照"。
γ=2 是论文推荐的标准值。γ=0 时退化为加权 BCE。

代码（utils.py:260-288）：


p          = sigmoid(logits)
bce        = BCEWithLogits(logits, targets, reduction='none')
p_t        = p*y + (1-p)*(1-y)            # 真类概率
focal_w    = (1 - p_t)**gamma             # 难样本权重
alpha_t    = alpha*y + (1-alpha)*(1-y)    # 类别平衡权重
loss       = (alpha_t * focal_w * bce).mean()
